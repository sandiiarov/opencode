Performs additive hashline edits in files.

Usage:
- You must have fresh anchors or a fresh version token for the file before editing it. Prefer reusing stable anchors from the latest `read`, `grep`, `edit`, or `write` result and pass `expectedVersion` from prior tool metadata when available. Re-read only when anchors are missing, ambiguous, or you need more context.
- Stable anchors can survive nearby line insertions and deletions, so prefer reusing the original anchor before re-reading.
- Keep edits additive and narrow. Prefer a few small anchored operations over rewriting unrelated surrounding code.
- Each edit call applies against the original file state. Do not renumber later edits in the same call.
- Use `replace` for line/range replacement, `append` to insert after an anchor or at EOF, and `prepend` to insert before an anchor or at BOF.
- `lines` must contain only the new file content to insert or replace. Do not include `LINE#ID` prefixes or diff markers.
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- Only use emojis if the user explicitly requests it. Avoid adding emojis to files unless asked.
- If an anchor no longer resolves uniquely, the tool will return updated anchors or candidate context. Reuse those exact anchors or re-read the file.
