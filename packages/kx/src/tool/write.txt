Writes a file to the local filesystem.

Usage:
- This tool will overwrite the existing file if there is one at the provided path.
- For existing files, read the file first so freshness checks can detect outside changes.
- Successful writes return `Updated lines` in `id|text` form. Reuse only the plain ids for the next `edit`. NEVER call `read` on that same file immediately after your own `write` just to verify the change, inspect the result, or get fresh ids. The returned `Updated lines` ids are already the fresh source of truth for follow-up edits in that area. Re-read only if you need additional context not covered by those returned lines.
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- NEVER proactively create documentation files (*.md) or README files. Only create documentation files if explicitly requested by the User.
- Only use emojis if the user explicitly requests it. Avoid writing emojis to files unless asked.
